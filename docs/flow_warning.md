# 流态安全预警

## 目标与边界

按已确认方案增加独立的第三个标签页，供实验人员离线分析视频或连续图像序列。原 Bubble Tracking、Gas Holdup 的算法、过滤、参数和导出格式保持原样。主界面仅增加页面注册、命名空间配置和关闭时的线程协调。

新模块位于 `flow_warning/`，仅复用共享 YOLO 推理工厂、图像读取和 ROI 类型，不导入原跟踪工作流。首版使用独立的几何关联器，不使用转角过滤，不向原运动 CSV 写入数据。

## 使用流程

1. 选择气泡分割模型、正常基线来源和待分析来源（视频或图像目录）。
2. 输入两段数据共同的实际采集帧率、长度标定和相同 ROI。抽帧序列须填写抽帧后的有效帧率；变速视频须填写对应的真实采集时间口径。
3. 调整窗口、最少尺寸/运动样本、持续窗口数和恢复窗口数，开始分析。
4. 查看三类状态和原因，点击事件或拖动回放滑块查看覆盖图。

基线和待测来源必须不同，图像尺寸必须一致。模型、ROI、标定和采样条件在一次运行内固定。源文件名的编号间隔不自动解释为时间；缺帧数据须先整理成等间隔序列。本模块不把处理 FPS 当作采集 FPS。

## 指标与质量

- 出现量：ROI 内有效原始分割掩膜并集面积百分比为主、实例数为辅，独立于轨迹质量。
- 大气泡：仅统计未触及图像或 ROI 边缘的完整掩膜；从正常基线的直径观测确定固定 D90 界限，监测超过该界限的数量比例与窗口 D90。重复帧观测代表视野内的时间占用分布，不代表独立气泡的生成频率。
- 运动：独立关联相邻帧完整掩膜，保留有符号的向上速度（`-vy`）、中位数、四分位距和下行比例。匹配距离超限、尺寸变化过大或关联含糊时不输出速度，保留原因。急转和下行本身不作为过滤条件。
- 有效空帧的数量与面积为零，尺寸/运动为缺失。读图失败、尺寸改变、检测有框但无掩膜等记为无效帧，不作为零气泡。
- 每个输入帧均参与计算；预览刷新频率只影响界面。

## 判定与事件

使用互不重叠的采集时间窗口，基线至少需要三个完整有效窗口。每项正常中心取基线窗口中位数，尺度取 `max(1.4826 × MAD, 噪声下限)`。噪声下限：面积 1 个百分点、比例 0.05、直径 2 像素对应长度、速度 0.5 像素/帧对应速度。默认偏离 3 个尺度为关注，连续两个窗口偏离为预警；回到触发界限的 2/3 内并持续两个窗口后恢复。大气泡比例、D90、速度离散度、下行比例仅检查升高；面积与典型竖直速度检查双向变化。

窗口有效帧覆盖率至少 80%；末尾不足一个完整窗口的数据仅导出为“数据不足”，不推动报警或恢复。尺寸与运动各自检查最少观测数，运动还检查可关联完整样本比例，避免从少量幸存轨迹推断整体状态。数据中断打断连续性，事件标记结束原因，不把缺失数据解释为恢复。

阈值是可调整的异常检测参数，尚非经实验验证的工况危险界限。首版不做自动停机、危险等级预测或流型分类。

## 输出

每次运行在所选输出目录内创建独立子目录，保存 `baseline.json`（配置、固定界限、正常范围）、`frames.csv`（含基线与待测逐帧质量）、`tracks.csv`（有符号速度、转角和过滤原因）、`windows.csv`、`events.json`、`events.csv` 和待测逐帧覆盖图。事件包含开始、触发、结束时刻、触发原因和证据帧。停止会保留已完成结果。

## 验收与开发

- 三个标签页分别保存参数，原两个工作流的测试继续通过。
- 测试包含空帧与坏帧、ROI 截断、下行与急转、关联含糊、采集时间、阈值固定、持续/恢复/数据缺失、逐帧处理及停止。
- 在 `hkc` 环境运行：`python -m unittest discover -s test -p "test_*.py"`；启动：`python main.py`。
- 使用现有 Python/PySide6/NumPy/SciPy/OpenCV 风格与依赖；新增文件不添加行内注释。禁止修改原算法和增加不必要依赖。
